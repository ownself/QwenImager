# Feature Specification: Qwen AI Image Generation Desktop App

**Feature Branch**: `001-qwen-imager-app`  
**Created**: 2026-02-27  
**Status**: Draft  
**Input**: User description: "利用Tauri开发一款跨平台桌面App，核心功能是通过与Qwen的图像/视频API交互来完成文生图、图生图以及图中文字翻译等功能。界面简洁大方，分为左侧历史栏和右侧交互栏，支持配置文件读取API密钥，支持剪贴板粘贴图片和多图上传。"

## Assumptions

- 应用程序安装包大小目标为 50MB 以内，以满足"小巧"的要求
- 配置文件路径固定为 `~/.qwenimage/setting.json`，不提供应用内配置编辑界面（首版）
- 对话历史持久化存储在本地，使用应用内置的轻量级存储方案
- 图片/视频生成为异步操作，需要轮询或等待结果返回
- 单次对话中上传的图片数量上限为 10 张（合理默认值，避免滥用）
- 生成的图片/视频下载后默认保存到用户的"下载"文件夹
- 应用支持 Windows、macOS、Linux 三大桌面平台
- 剪贴板粘贴的图片以临时文件形式保存，在会话结束或应用关闭时清理

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 文生图：输入文字生成图片 (Priority: P1)

用户打开应用，在右侧交互栏的文本输入框中输入描述性文字（Prompt），点击提交按钮后，系统调用 Qwen 文生图 API 生成图片，并将生成的图片以对话消息的形式展示在上方的对话区域中。用户可以选中生成的图片进行复制或下载。

**Why this priority**: 文生图是最基础、最核心的功能，也是用户最常用的场景。它独立成立，无需任何前置图片输入，是 MVP 的核心价值。

**Independent Test**: 可以通过输入一段文字描述并提交来完整测试，验证图片是否成功生成并展示在对话区域中。

**Acceptance Scenarios**:

1. **Given** 用户已正确配置 API 密钥且应用已启动, **When** 用户在文本框中输入 Prompt 并点击提交, **Then** 系统发送请求到 Qwen 文生图 API，对话区域显示加载状态，随后展示生成的图片
2. **Given** 对话区域中已展示一张生成的图片, **When** 用户右键点击或选中该图片, **Then** 系统提供"复制"和"下载"两个操作选项
3. **Given** 用户选择下载图片, **When** 用户点击"下载"选项, **Then** 图片被保存到用户的下载文件夹，并提示下载成功
4. **Given** API 密钥未配置, **When** 用户尝试提交 Prompt, **Then** 系统提示用户需要配置 API 密钥，交互功能处于禁用状态

---

### User Story 2 - 图生图：上传参考图片生成新图片 (Priority: P2)

用户在文本输入框旁通过上传按钮选择一张或多张参考图片，同时输入文字描述，提交后系统调用 Qwen 图生图 API，根据参考图片和文字描述生成新图片。上传的图片在界面上按顺序排列展示，用户可以调整顺序。

**Why this priority**: 图生图是文生图的自然扩展，为用户提供更精确的创作控制，是第二核心功能。

**Independent Test**: 可以通过上传一张参考图片并输入描述来测试，验证系统能否正确组合图片和文字发送请求并展示结果。

**Acceptance Scenarios**:

1. **Given** 用户已配置 API 密钥, **When** 用户点击上传按钮并选择一张或多张图片, **Then** 选中的图片以缩略图形式按顺序展示在输入区域，并明确标注顺序编号
2. **Given** 用户已上传多张图片, **When** 用户拖拽或通过其他方式调整图片顺序, **Then** 图片的显示顺序更新，提交时按新顺序发送
3. **Given** 用户已上传参考图片并输入 Prompt, **When** 用户点击提交, **Then** 系统按照图生图 API 格式发送请求，对话区域展示生成结果
4. **Given** 用户在任意界面复制了一张图片到剪贴板, **When** 用户在文本输入区域按 Ctrl+V, **Then** 剪贴板中的图片被添加到上传图片列表中，与手动上传的图片行为一致

---

### User Story 3 - 图片文字翻译 (Priority: P3)

用户上传一张包含文字的图片，选择源语言和目标语言，提交后系统调用 Qwen 图片翻译 API，返回翻译后的图片并展示在对话区域中。

**Why this priority**: 图片翻译是一个独立的专项功能，面向有跨语言图片处理需求的用户，是核心功能的补充。

**Independent Test**: 可以通过上传一张包含中文的图片并选择翻译为英文来测试，验证翻译后的图片是否正确展示。

**Acceptance Scenarios**:

1. **Given** 用户已配置 API 密钥, **When** 用户上传一张包含文字的图片并选择翻译模式，设置源语言和目标语言后提交, **Then** 系统调用翻译 API 并在对话区域展示翻译后的图片
2. **Given** 翻译结果已展示, **When** 用户选中翻译后的图片, **Then** 用户可以复制或下载翻译后的图片

---

### User Story 4 - 对话历史管理 (Priority: P4)

用户可以查看左侧历史栏中的历史对话列表，点击某条历史记录后，右侧交互栏恢复到该对话的完整内容（包括用户输入和生成结果）。用户还可以折叠左侧历史栏以获得更大的工作区域。

**Why this priority**: 历史管理为用户提供对话追溯和工作连续性，但不影响核心生成功能的使用。

**Independent Test**: 可以通过完成几次生成操作后，在历史栏中点击不同记录来测试，验证对话是否能完整恢复。

**Acceptance Scenarios**:

1. **Given** 用户已完成多次图片生成操作, **When** 用户查看左侧历史栏, **Then** 每条对话以摘要形式（如首条 Prompt 的前几个字）展示在列表中，按时间倒序排列
2. **Given** 历史栏中有多条记录, **When** 用户点击某条历史记录, **Then** 右侧交互栏恢复到该对话的完整内容，包括所有用户输入和生成的图片/视频
3. **Given** 左侧历史栏处于展开状态, **When** 用户点击折叠按钮, **Then** 历史栏收起，右侧交互栏扩展占满可用空间
4. **Given** 用户正在一个新的对话中, **When** 用户提交第一条 Prompt, **Then** 系统自动在历史栏中创建一条新的对话记录

---

### User Story 5 - 配置加载与状态提示 (Priority: P5)

应用启动时自动读取用户主目录下的配置文件，加载 API 密钥和模型端点信息。如果配置文件不存在或格式错误，应用以受限模式启动，所有 API 交互功能处于禁用状态，并向用户展示明确的提示信息。

**Why this priority**: 配置加载是应用运行的前提条件，但其本身不是用户直接交互的功能，属于基础设施。

**Independent Test**: 可以通过分别在有配置和无配置的情况下启动应用来测试，验证应用的行为是否符合预期。

**Acceptance Scenarios**:

1. **Given** 用户主目录下存在格式正确的 `~/.qwenimage/setting.json`, **When** 应用启动, **Then** 系统成功加载 API 密钥和模型配置，所有功能正常可用
2. **Given** 配置文件不存在, **When** 应用启动, **Then** 系统显示友好提示告知用户如何创建配置文件，所有 API 交互功能处于禁用状态
3. **Given** 配置文件存在但格式错误（如缺少必要字段）, **When** 应用启动, **Then** 系统显示具体的错误信息指出问题所在，API 功能禁用

---

### Edge Cases

- 当 API 请求超时或返回错误时，系统应在对话区域显示错误信息，并允许用户重试
- 当用户上传的图片文件过大（超过 10MB）时，系统应提示用户并拒绝上传或自动压缩
- 当网络连接中断时，系统应在提交前检测并提示用户网络不可用
- 当用户快速连续点击提交按钮时，系统应防止重复请求
- 当剪贴板中没有图片数据时，Ctrl+V 操作应被忽略或提示无可用图片
- 当配置文件中的 API 密钥无效（被服务端拒绝）时，系统应提示密钥无效并建议用户检查配置
- 当对话历史数据量过大时，系统应采用分页或虚拟滚动策略保持界面流畅
- 当用户上传非图片格式的文件时，系统应拒绝并提示仅支持图片格式

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供文生图功能，用户输入文字 Prompt 后能生成对应的图片
- **FR-002**: 系统必须提供图生图功能，支持用户上传一张或多张参考图片并结合文字 Prompt 生成新图片
- **FR-003**: 系统必须提供图片文字翻译功能，用户上传含文字的图片后能生成翻译后的图片
- **FR-004**: 系统必须在启动时从 `~/.qwenimage/setting.json` 读取 API 配置信息
- **FR-005**: 系统必须在配置缺失或无效时以受限模式运行，禁用所有 API 交互功能并提示用户
- **FR-006**: 系统必须以对话形式展示用户的输入和 API 返回的结果（图片/视频）
- **FR-007**: 用户必须能够对对话中的图片/视频资源执行复制和下载操作
- **FR-008**: 系统必须支持通过文件选择器上传多张图片用于图生图功能
- **FR-009**: 上传的多张图片必须在界面上明确显示顺序，并支持用户调整顺序
- **FR-010**: 系统必须支持通过 Ctrl+V 从剪贴板粘贴图片到上传列表
- **FR-011**: 系统必须提供左侧可折叠的历史对话栏，展示所有历史对话的摘要
- **FR-012**: 用户必须能够通过点击历史记录恢复到该对话的完整内容
- **FR-013**: 系统必须持久化存储对话历史，确保应用重启后历史数据不丢失
- **FR-014**: 系统必须在 API 请求期间显示加载/处理状态，让用户了解当前进度
- **FR-015**: 系统必须处理 API 错误并向用户展示可理解的错误信息
- **FR-016**: 系统必须防止用户在请求处理期间重复提交
- **FR-017**: 系统必须作为跨平台桌面应用在 Windows、macOS 和 Linux 上运行
- **FR-018**: 图片翻译功能必须支持用户选择源语言和目标语言

### Key Entities

- **对话 (Conversation)**: 代表一次完整的用户交互会话，包含多条消息，具有创建时间、摘要标题等属性
- **消息 (Message)**: 对话中的单条记录，分为用户消息和系统响应两种角色，可包含文字、图片、视频等内容
- **配置 (Configuration)**: 用户的 API 配置信息，包含提供商、API 密钥、各模型的端点 URL 等
- **附件 (Attachment)**: 用户上传或从剪贴板粘贴的图片文件，具有文件路径、顺序编号、文件大小等属性
- **生成结果 (GenerationResult)**: API 返回的图片或视频资源，包含资源 URL/数据、生成参数、创建时间等属性

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从输入 Prompt 到看到生成的图片，整个操作流程不超过 60 秒（不含 API 处理时间）
- **SC-002**: 用户首次使用应用时，90% 的用户能在 5 分钟内独立完成一次文生图操作
- **SC-003**: 上传和排序多张参考图片的操作在 30 秒内完成
- **SC-004**: 通过 Ctrl+V 粘贴图片到上传列表的操作在 2 秒内完成
- **SC-005**: 历史对话的恢复操作在 3 秒内完成，对话内容（包括图片）完整展示
- **SC-006**: 应用安装包大小不超过 50MB
- **SC-007**: 应用冷启动时间不超过 5 秒
- **SC-008**: 当 API 出现错误时，100% 的错误情况都向用户展示可理解的错误信息
- **SC-009**: 在包含 100 条以上历史对话的情况下，历史栏的滚动和操作保持流畅，无明显卡顿
